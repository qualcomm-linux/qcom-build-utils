# Runtime files

Everything in this directory is staged verbatim into the rootfs image by
`build-rootfs.sh` (Step 9.6), preserving modes and symlinks. Paths here mirror
their absolute location on the target, so `usr/sbin/foo` becomes `/usr/sbin/foo`
in the image.

This file is excluded from the image.

Adding a runtime file means adding it here. `build-rootfs.sh` does not need to
change.

## Rules

**Static content only.** Anything parameterised by the build (versions, build
IDs, timestamps) must be generated by `build-rootfs.sh` into a known path and
read at runtime. Templating this tree would reintroduce the escaping and
lint problems that moving out of the chroot heredocs was meant to solve.

**No top-level `bin/`, `sbin/`, `lib/` or `lib64/`.** Those are symlinks into
`/usr` on the target under the merged-`/usr` layout. Staging a real directory
over them would replace the symlink and break the layout for everything else.
Use `usr/bin/`, `usr/sbin/`, `usr/lib/` instead.

**Enable systemd units with a committed `.wants` symlink**, for example:

```
etc/systemd/system/multi-user.target.wants/foo.service -> ../foo.service
```

That is exactly what `systemctl enable` produces, so no `systemctl` call is
needed inside the chroot and staging stays a pure file copy. The build asserts
that every `.wants` entry is a real symlink and fails if one arrives as a
regular file, which is what happens on a checkout without symlink support.

## Staging behaviour

Files land after all package installation, so a file here silently takes
precedence over a package-provided file at the same path. That is intended for
an overlay, but the build prints a `[WARN] runtime overwrites existing /path`
line for each such collision so it is visible in the log rather than silent.

Everything is extracted as `root:root`. Existing directories in the rootfs keep
their own ownership and permissions.

## Image metadata

Callers can provide build-generated metadata without modifying this tracked
tree by passing repeatable `--image-info <name=file>` arguments to
`build-rootfs.sh`. Each file is installed as root-owned mode `0644` under
`/usr/lib/qcom-image-info/`.

The static `image_info` dispatcher reads metadata as opaque text. It never
executes or sources file contents. `build_info` and `kernel_info` are aliases
for the corresponding metadata names.

## Checking your work

```sh
shellcheck rootfs/runtime/usr/sbin/*.sh
systemd-analyze verify rootfs/runtime/etc/systemd/system/*.service
```
